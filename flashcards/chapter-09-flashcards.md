## Chapter 9: Training Management, Data Preparation, and the Two Go/No-Go Gates — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Go/no-go gate 1 — what does it verify? | That data is clean, complete, consistent, properly labeled, and representative of the production population — BEFORE modeling begins. Exam tip: model performance is never a gate 1 criterion. |
| 2 | Go/no-go gate 2 — the four required elements? | Performance (vs. threshold), robustness (edge cases/adversarial/noisy input), generalization (holdout/production-like data), and documented stakeholder approval. Exam tip: high accuracy alone is not sufficient. |
| 3 | Data augmentation vs. synthetic data generation | Augmentation transforms existing real records (flip, crop, noise, rotation). Synthetic generation creates entirely new artificial records (GANs, simulation). Exam tip: augmentation extends real data; synthetic data fills gaps real data can't cover. |
| 4 | Random k-fold CV vs. time-series (rolling-window) CV | Random k-fold shuffles data and risks future data leaking into training on temporal datasets. Time-series CV uses forward-chaining/rolling windows to preserve chronological order. Exam tip: random k-fold on time-series data is a classic wrong-answer trap. |
| 5 | Minimum elements an experiment tracking system must log | Code version, data version, hyperparameters, random seed, environment/dependency versions, and resulting metrics. Exam tip: missing data versioning breaks reproducibility even if code is versioned. |
| 6 | Purpose of data versioning | Allows the exact dataset used to produce a given model to be reconstructed later. Exam tip: exam distinguishes model versioning (tracks model artifacts) from data versioning (tracks dataset snapshots) — both are required for full reproducibility. |
| 7 | Robustness testing at gate 2 — what must it include? | Evaluation against edge cases, noisy/adversarial inputs, and distribution shift — not just clean test-set accuracy. Exam tip: passing a clean holdout test alone does NOT satisfy the robustness requirement. |
| 8 | Common conventional dataset split ratios | 70/15/15 or 80/10/10 (train/validation/test) are common conventions; exact ratio depends on dataset size. Exam tip: time-series data must be split chronologically, never randomly. |
| 9 | Common k values in k-fold cross-validation | k=5 and k=10 are the most common choices. Higher k lowers bias in the performance estimate but increases compute cost. Exam tip: choice depends on dataset size and available compute budget, not a fixed rule. |
| 10 | Managing a plateaued hyperparameter tuning job — PM action? | Apply an early-stopping/compute-budget cutoff and select the best configuration found so far rather than continuing to burn compute for negligible gains. Exam tip: exam tests judgment on balancing marginal gains vs. compute cost. |
| 11 | Documented approval requirement at gate 2 | Requires explicit sign-off from relevant business and technical stakeholders with recorded rationale — not just an automated metric threshold being met. Exam tip: CPMAI emphasizes governance and documentation, not purely technical pass/fail. |
| 12 | Cause of non-reproducible training results with identical data/hyperparameters | Unseeded randomness or non-deterministic operations (e.g., unset random seed, GPU nondeterminism, data shuffling order). Exam tip: fix by seeding all random number generators and pinning dependency/environment versions. |
