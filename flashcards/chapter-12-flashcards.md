## Chapter 12: Full Exam Simulation and Test-Day Strategy — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Exam time budget: 120 questions / 160 minutes — pace per question? | ~80 seconds/question. Exam tip: check pace every ~20 questions (should be ~26–27 min elapsed per 20 questions) to catch drift early. |
| 2 | Retake policy: max attempts and eligibility window? | 3 attempts within a 12-month eligibility period. Exam tip: failing attempt #1 does not remove eligibility for #2 and #3 within that window. |
| 3 | Pearson VUE check-in: how many forms of ID required? | 2 forms of ID; at least 1 must be government-issued with a photo, and names on both must exactly match registration. Exam tip: mismatched middle names/initials can cause denial of entry. |
| 4 | Pearson VUE (test center) vs OnVue (online proctored) — key logistics difference | Pearson VUE: travel to a physical center, staff-managed check-in, controlled room provided. OnVue: exam taken from home/office, candidate must self-clear the room and pass a live 360° webcam scan before start. |
| 5 | OnVue environment check — what fails the room scan most often? | Visible papers, phones, extra monitors, or other people in the room. Exam tip: clear the desk completely and disconnect/cover secondary monitors before scan. |
| 6 | Flag-and-return: correct sequence of actions on an uncertain question | 1) Eliminate clearly wrong options, 2) select the best current guess as a placeholder, 3) flag it, 4) move on, 5) return only if time remains. Never leave it blank. |
| 7 | Elimination technique — first rule when 2 options look correct | Discard any option that is 'correct but under different conditions' than the scenario states. Only the option matching the exact stated constraints survives. |
| 8 | Phase-identification question pattern — key language clue | Scenario describes an activity in progress (e.g., cleaning data, building a model) and asks 'which phase is this?' Match the described ACTIVITY to the phase, not the project's overall goal. |
| 9 | Gate-decision question pattern — key language clue | Scenario describes a completed activity plus a pending decision to proceed/halt/iterate. Correct answers require BOTH technical validation AND business/stakeholder sign-off before advancing. |
| 10 | Common gate-decision distractor to watch for | 'Technical criteria met → proceed immediately' is almost always wrong if business/sponsor validation is not mentioned as completed. Gates need dual sign-off. |
| 11 | Time-pacing checkpoint rule of thumb | If elapsed time ÷ questions answered > 80 sec/question, you are behind pace — increase flagging of hard items rather than trying to solve every one fully. |
| 12 | Placeholder-answer rule before flagging | Always select a best-guess answer BEFORE flagging a question. An unanswered flagged item at time-expiry scores as wrong; a placeholder guess has a chance of being correct. |
