## Chapter 6: AI Workspace, Infrastructure, and Data Gathering — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | ETL vs ELT — key difference? | ETL transforms data BEFORE loading into the target system; ELT loads raw data first and transforms after. Exam tip: ELT is common with modern cloud data lakes/warehouses for AI data gathering. |
| 2 | Data lake vs data warehouse — which stores raw, unstructured + structured data in native format? | Data lake (schema-on-read). Data warehouse stores structured, schema-on-write data optimized for BI. Exam tip: AI/ML training data typically originates in a data lake. |
| 3 | DVC / Git LFS — what problem do they solve? | Both version large binary/data files that plain Git handles poorly, without bloating the repo. DVC also tracks ML pipeline and dataset lineage. Exam tip: required for reproducible AI data and model versioning. |
| 4 | Batch vs streaming refresh — when is streaming required? | When the use case needs near-real-time decisions (fraud detection, live recommendations). Batch suffices for periodic reporting/training refreshes. Exam tip: match cadence to business latency need, not convenience. |
| 5 | Commonly cited industry estimate: % of a data scientist's time spent on data preparation vs modeling? | ~80% on data preparation/wrangling, ~20% on modeling (widely cited industry survey figure). Exam tip: explains why 'Identify Data Needs' carries heavy exam weight (26%). |
| 6 | What is a 'sandbox' environment in secure AI development? | An isolated environment — often using de-identified/masked data — where data scientists can explore and build without exposing production or sensitive data. Exam tip: correct answer whenever a scenario involves PII/PHI and dev access. |
| 7 | Schema-on-write vs schema-on-read — which applies to data lakes? | Schema-on-read (schema applied at query/use time). Data warehouses use schema-on-write. Exam tip: schema-on-read gives flexibility for diverse AI data types. |
| 8 | Completeness validation — two common checks after extraction? | Record count reconciliation (source vs destination) and checksum/hash comparison. Exam tip: perform BEFORE feature engineering or modeling begins. |
| 9 | GPU vs CPU compute — when is GPU required? | For deep learning/neural network training on large image, video, or NLP transformer datasets requiring parallel matrix ops. CPU is fine for lightweight classical ML. Exam tip: match compute type to model complexity and data volume. |
| 10 | Elastic on-demand cloud compute vs fixed on-prem cluster — best for variable AI workloads? | Elastic on-demand cloud compute — scales up during training bursts and down between sprints, minimizing idle cost. Exam tip: choose elastic provisioning whenever demand is described as 'variable' or 'bursty'. |
| 11 | What does a 'data refresh procedure' define in an AI pipeline? | The frequency and method (batch, micro-batch, streaming) by which new/updated data enters the AI workspace to keep training/inference data current. Exam tip: cadence must match model drift tolerance and business latency needs. |
| 12 | Which collaboration tooling category is essential for data teams beyond code version control? | Data/model versioning and experiment tracking tools (e.g., DVC, MLflow) plus shared notebook/workspace platforms. Exam tip: distinguishes code-only VCS (Git) from data/experiment versioning needs unique to AI projects. |
